# 프로젝트 개요

## 시작 배경

개발자에게 전달받은 회원·상품·주문 웹소스를 테스트 환경에 배포해 기본 동작을 확인했습니다. 이후 앱의 기본 구조를 유지하면서 배포 자동화와 운영 기능에 필요한 리소스를 변경·추가했습니다.

프로젝트의 중심은 새로운 쇼핑몰 전체 개발보다 **기존 서비스를 받아 배포하고 변경하며 운영하는 과정**입니다. 관리자 화면·장바구니·주문 알림과 오류 수정처럼 필요한 앱 보완도 함께 진행했습니다.

## 진행 순서

1. 초기 테스트 환경에서 접속·회원·상품·주문 기능 확인
2. Terraform으로 반복 구축할 AWS 환경 구성
3. 변경 서비스 테스트·빌드와 동료 승인 배포 연결
4. V1·V2·롤백·V3로 버전 변경과 복구 시연
5. 파드 교체·자동 확장·비밀번호 변경·장애 전환·주문 알림 확인
6. 스냅샷으로 업무 데이터와 운영 기록 복원
7. 다른 AWS 환경에 재배포해 절차 재사용 여부 확인

초기 테스트와 자동화 환경의 첫 기준 버전 V1은 구분합니다. V2 상세 오류는 격리된 시험 환경에서 재현했으며, 자연 발생한 운영 장애라고 설명하지 않습니다.

## 기존과 최종 구성

| 영역 | 초기 테스트 구성 | 최종 코드 |
| --- | --- | --- |
| 접속·인증서 | NLB·NGINX Ingress·cert-manager | 공유 ALB·ACM·도메인 분기 |
| 데이터 | RDS·S3 | RDS Multi-AZ·S3·AZ별 NAT |
| 구축·배포 | 로컬 빌드·기본 Actions·Git 반영 | Terraform·원격 state·변경 서비스 빌드·승인 PR·digest·내부 검사 |
| 비밀번호 | Secret 수동 입력 | Secrets Manager·ESO·앱 갱신 |
| 운영 | 자동 확장·기본 대시보드 | 경보·EBS 저장·AWS 로그·감사 이력 |
| 주문 알림 | 주문 저장 중심 | Outbox·SQS 소비·SES 메일·중복 기록·DLQ |

## 팀 기여와 저장소

팀 최종 코드를 기준으로 배포·운영 기반, 주문·재고 처리, 비동기 이메일과 검증 방식을 통합했습니다. 이번 저장소는 원본 이력을 보존한 개인 제출·정리본이며 GitHub 계정·저장소·AWS 환경 참조를 소유자 기준으로 변경했습니다.

원본의 이전 단계 문서는 지우지 않고 보관했습니다. 현재 코드, 과거 실측 결과, 이번 로컬 검사와 미실행 항목은 각각 구분해 읽습니다.
