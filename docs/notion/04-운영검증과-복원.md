# 운영 검증과 복원

## 기록을 읽는 기준

이 문서는 팀 최종 코드, 기존 문서와 사용자가 제공한 최종 발표·검증 캡처를 기준으로 정리했습니다. 과거 검증 사진 전체가 이 저장소에 포함된 것은 아닙니다. 이번 저장소 복사에서는 AWS 명령을 실행하지 않았고 실제 인프라의 현재 상태도 조회하지 않았습니다. 새 계정 설정으로 재배포에 성공했다고 주장하지 않습니다.

## 운영 시험

| 시험 | 변경·입력 | 관찰한 결과와 의미 |
| --- | --- | --- |
| 파드 교체 | Frontend·백엔드·Grafana 교체 | 새 파드와 준비 상태, 같은 주문·재고·저장 대시보드 대조 |
| HPA | Member CPU 부하 후 종료 | 목표 CPU 기준 파드 증가 후 감소 |
| Cluster Autoscaler | 자원 요청이 큰 임시 파드 생성 후 제거 | Pending에서 노드 추가·Running, 이후 노드 축소 |
| RDS 전환 | Multi-AZ 강제 장애 조치 | 같은 endpoint의 IP·AZ 변화, 연결 실패 후 회복, 상품·재고 대조 |
| 비밀번호 변경 | RDS 비밀번호 회전 | Secret·DB 상태, ESO 동기화, 앱 재연결과 로그인 확인 |
| 주문 메일 | 주문·이벤트 발행 | 구매자·관리자 실제 수신과 처리 기록 확인 |
| DLQ | 실패 메시지 재시도 | DLQ 보관과 CloudWatch ALARM, 시험 메시지 정리 후 OK |
| NAT 별도 시험 | 경로 임시 차단·제어기 실행 | 실패 감지·다른 NAT 우회·원래 경로 복귀 |

자동 확장, DB 전환, 비밀번호 변경은 각각 다른 시험입니다. 노드를 두 AZ에 둔다고 전체 서비스의 AZ 장애 무중단까지 증명되지는 않습니다. RDS 전환 중 연결 실패가 관측됐고 일부 백엔드·운영 도구는 단일 파드입니다.

NAT 자동 우회·복귀는 별도 시험 환경의 EventBridge·Lambda 제어기 결과입니다. 기본 Terraform에서 NAT 두 개를 만드는 것과 동일하지 않으며, 해당 별도 제어기 구현 전체가 이 복사본에 포함돼 있다고 가정하지 않습니다.

## 백업과 복원

1. 비교할 계정·상품·주문·재고·이미지·운영 기록을 먼저 기록합니다.
2. RDS 스냅샷 1개와 모니터링 EBS 스냅샷 3개 완료를 확인합니다.
3. 시험 범위의 EKS·RDS를 제거하되 VPC·NAT·S3·ECR·state와 스냅샷은 유지합니다.
4. 실행 환경은 코드로, RDS와 모니터링 볼륨은 스냅샷으로 다시 만듭니다.
5. 로그인·업무 데이터·S3 이미지·Grafana·Prometheus·Alertmanager의 여섯 항목을 비교합니다.

S3는 유지한 자원이므로 이미지 보존을 대조한 것이고 DB·EBS는 스냅샷 복원 결과입니다. 복구 비밀 정보는 Windows DPAPI를 사용하므로 같은 사용자·PC 조건이 있습니다. 보존 중에도 남긴 자원에는 비용이 발생합니다.

## 다른 환경 재배포

새 AWS 환경에 계정·도메인·권한 설정을 바꾸어 코드와 절차를 재사용하고 새 주문 데이터를 만들어 기능·승인·권한·롤백 등을 확인한 기록입니다. 기존 DB를 다른 계정으로 이전한 시험과 구분합니다.

이번 `Final_Project` 복사에서는 본인 계정과 저장소로 코드 참조만 변경했습니다. 이 복사본의 로컬 검사와 새 AWS 실검증은 별개입니다. [이번 검사 결과](https://github.com/yonginfra/Final_Project/blob/main/docs/final/08-local-checks.md)
